# 在 OPPO / ColorOS 手机上使用（Reno 15 实测路径）

本文针对 ColorOS 手机（Reno 15 中国版为 ColorOS 16 / Android 16）。
核心难点有**两个，来源不同**，别混在一起：

| 难点 | 来源 |
|---|---|
| **Android 13 起侧载应用的无障碍开关默认是灰的** | **Android 通用**，不是 ColorOS 的锅。任何 13+ 的手机（三星/小米/vivo…）都这样 |
| **ColorOS 会自己把无障碍权限回收掉** | **ColorOS 专有**。实机上它维护一份「跳过广告类应用」豁免名单（`accessibility_turn_off_skip_package`，54 条，含李跳跳等），**本应用的包名不在名单里** —— 机制与证据见 `next-steps.md` 第五节 |

这两件事不解决，装上也用不了。

> 也就是说：**"权限被系统收回"这类问题各 ROM 都有**（小米的省电策略、vivo 的后台高耗电、华为的应用启动管理），
> ColorOS 的特殊之处是它用一份**包名白名单**来豁免，而我们不在名单上。
> 不要以为换个品牌的手机就不用做下面这些设置。

---

## 两条路线，先选一条

| | 路线 A：电脑 + USB | 路线 B：只用手机 |
|---|---|---|
| 难度 | 低，一条命令 | 中，要手点好几步 |
| 能否绕过「受限制的设置」 | ✅ 直接绕过，不用管那个灰色开关 | ❌ 必须手动放行 |
| 能否看实时日志 | ✅ `adb logcat` | 只能在应用里看日志面板 |
| 需要 | 数据线 + 电脑装了本工程 | 无 |

---

## 路线 A：电脑 + USB（推荐）

### 1. 手机开启开发者模式

1. 设置 → 关于本机 → 版本信息 → 连点「**版本号**」7 次
2. 回到 设置 → 系统设置 → **开发者选项** → 打开「**USB 调试**」
   - 顺手把「**USB 安装**」也打开（如果 ColorOS 有这个选项，能避免安装被拦）

### 2. 连电脑并授权

数据线连上电脑（**要能传数据的线，纯充电线不行**）。
手机上会弹出「是否允许 USB 调试」→ 勾选「始终允许」→ 允许。

### 3. 跑一条命令

```powershell
cd <项目所在目录>\adskip
powershell -File tools/install-and-enable.ps1
```

这个脚本做四件事：

1. 确认设备已连接（会打印机型和 ColorOS 版本）
2. 安装 APK
3. **读出手机上已有的无障碍服务列表，把本应用追加进去**——不会覆盖，你原有的 TalkBack 之类不会被关掉
4. 写 `accessibility_enabled = 1` 并校验

### 4. 看实时日志

```powershell
powershell -File tools/install-and-enable.ps1 -Logcat
```

然后去手机上打开有开屏广告的应用，电脑上会打印判定过程。

## 路线 B：只用手机

### 1. 把 APK 传到手机

`app\build\outputs\apk\debug\app-debug.apk`（5.5 MB）用微信/QQ/网盘传到手机。

**ColorOS 的一个技巧**：如果你发现「允许受限制的设置」这个选项在系统里**根本找不到**，
就**不要**从微信里直接点安装，而是先把 APK 存到手机，用**手机自带的「文件管理」**打开它安装。
这样走一遍"本地安装"之后，「允许受限制的设置」选项往往就出现了。

安装时 OPPO 会做安全检测并提示"未知来源"，允许即可。

### 2. 安装后打开「广告跳过」，点【打开无障碍设置】

系统无障碍设置的路径（ColorOS 各版本略有差异，任选其一）：

- 设置 → 其他设置 → **无障碍** → **已安装的服务**（部分版本是「通用」→「已下载的应用」）
- 设置 → 系统设置 → **无障碍** → 已安装的服务
- 手机管家 → 权限隐私 → **无障碍**

> 找不到就用**设置顶部的搜索框**搜「无障碍」——ColorOS 各版本菜单改动频繁，搜索比记路径可靠。

### 3. 开关是灰的 / 提示「受限制的设置」

这是 Android 13+ 对侧载应用的默认限制。两条解法：

**解法一（首选）**：允许受限设置

- 桌面**长按「广告跳过」图标** → 应用信息 → **允许受限制的设置**
- 或者：设置 → 应用 → 应用管理 → 广告跳过 → **右上角 ⋮** → 允许受限制的设置

打开后回到无障碍页面，开关就能点了。

**解法二**：用路线 A 的 adb 命令，完全不用管这个开关。

### 4. 开启服务

在「已安装的服务」里找到**广告跳过** → 点进去 → 开启「**使用服务**」→ 系统会弹出权限提示
（无障碍服务可以查看屏幕内容、模拟操作）→ **确定**。

---

## ⚠️ ColorOS 必须处理的两件事（否则会"用着用着就失效"）

### 1. 关掉「权限自动回收」

ColorOS 会在一段时间后自动撤销长期未"使用"的权限，**无障碍权限也在其中**。
表现就是：刚设置好能用，过几小时或重启后就悄悄失效了。

- 手机管家 → 权限隐私 → **权限自动回收** → 关闭
- 或在设置顶部搜索框搜「**自动回收**」

### 2. 允许本应用后台活动

本应用需要常驻后台才能持续监听。

- 设置顶部搜索框搜「**自启动**」→ 找到「广告跳过」→ 打开
- 再搜「**耗电管理**」或「**电池优化**」→ 找到「广告跳过」→ 设为「**允许后台活动 / 不优化**」

> 用搜索框，不要照着路径找——ColorOS 的电池相关菜单位置改动很频繁。

## 怎么确认它在工作

### 方法一：应用内的调试日志面板

打开「广告跳过」，往下滑到「调试日志」。
这个面板不是顺手加的，而是目前唯一能判断"识别到没有、点对没有"的手段。

### 方法二：电脑看 logcat（更清楚）

```powershell
powershell -File tools/install-and-enable.ps1 -Logcat
```

### 日志对照表

| 日志内容 | 含义 | 下一步 |
|---|---|---|
| `服务已连接｜规则库 v1｜规则数 6` | 服务正常运行 | 没问题 |
| `[微博] 已点击(第1次)：文本命中「跳过」...` | **成功识别并点击**（正常情况下一次点击就够） | 没问题 |
| `[微博] 放弃介入：存在输入框，判定为登录/正常页面` | 熔断生效，主动不动手 | 正常行为 |
| `[微博] 本次启动未发现跳过按钮` | 这一次没有广告，或广告先消失了 | 正常；若反复出现说明没识别到 |
| `[微博] 发现 N 个跳过候选，但都被安全规则否决：「…」TextView@(…)` | **候选被防误点规则拒绝** | 把这行原文发我，里面含类名、view id 和坐标 |
| `[微博] 已超出时间窗（3223ms > 3000ms），本次启动不介入` | 界面读得太慢，错过了 3 秒窗口 | 告诉我，可以考虑放宽该应用的 windowMs |
| `[微博] 读不到界面内容（rootInActiveWindow 为空）` | 这个应用的开屏窗口不接受无障碍读取 | 这种情况文本方案无法覆盖，只能靠坐标兜底 |
| `[微博] 点击后「跳过」仍存在，可能未生效` | 点了但没跳掉 | 告诉我应用名 |
| `疑似误点：前台已跳转到 com.xxx.browser` | **点错了**，已自动返回 | 这条最重要，务必告诉我 |
| 打开应用时**完全没有**任何日志 | 事件没进来 | 检查无障碍开关是否还在（可能被权限回收了） |

## 日常使用

**开启之后不需要任何操作。** 正常打开应用就行，它会在后台自己判断和点击。

想临时停用：去无障碍设置里关掉「使用服务」。不想要了就卸载。

---

## 出问题先查这三点

1. **无障碍开关还在吗？** ColorOS 的「权限自动回收」经常把它关掉，这是"用着用着失效"的第一嫌疑
2. **应用被后台清理了吗？** 检查自启动和耗电管理
3. **重启手机后失效** → 回到第 1 点

---

## 已知限制（不是 bug，是方案本身的边界）

- **摇一摇广告拦不住**：它靠加速度计触发，应用层无解，只能等系统提供开关
  （vivo OriginOS 5 已有「仅开屏禁止」，ColorOS 目前没有）
- **银行、支付、政务类应用建议不要接管**：这类应用检测到无障碍服务开启后可能拒绝运行或有安全提示。
  内置规则库没有包含它们，你也可以随时把某个应用从 `app/src/main/assets/rules.json` 里删掉重装
- **规则库目前有 18 个应用**：微博、知乎、贴吧、B站、微信读书、闲鱼、菜鸟、京东、123云盘、网易云音乐、腾讯视频、爱奇艺、掌上无畏契约、KOOK、易校园、云运动、志愿汇、学习通。
  包名全部由设备确认，但**各应用的支持程度不同**（详见 README 的真机验证表）。其它应用需要按日志反馈来补规则

## 卸载与重装

`app-debug.apk` 是 **debug 签名**。如果将来用不同签名重新打包，
直接覆盖安装会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，需要先卸载旧版：

```powershell
& "$PWD\.android-sdk\platform-tools\adb.exe" uninstall io.github.adskip
```
